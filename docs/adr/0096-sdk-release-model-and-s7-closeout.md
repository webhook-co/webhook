# ADR 0096 — SDK release model + S7 (SDKs & OpenAPI) close-out

- status: accepted
- date: 2026-07-04
- scope: `packages/sdks`, `docs/releasing-sdks.md`, and the S7 epic as a whole
- review severity: low (documentation + a manifest package; no runtime or auth surface)

## context

Epic S7 set out to turn the frozen public API surface into a contract-synced OpenAPI 3.1 specification and
ship signed, multi-language SDKs generated from it. Slices 0–4 delivered that; this ADR records the
cross-cutting **release model** and closes out the epic. It supersedes the placeholder in `packages/sdks`
(which referenced a closed-vendor codegen path that was never taken).

## what shipped (S7 Slices 0–4)

- **Slice 0 (ADR-0088)** — a declarative `ROUTES` manifest consumed by both the runtime router and the
  spec generator, plus an OpenAPI 3.1 document derived from the Zod contract via `z.toJSONSchema`, with a
  3-layer drift guard. HTTP-layer drift is structurally impossible.
- **Slice 1 (ADR-0090)** — the machine-readable spec served at `GET api.webhook.co/openapi.json` (public,
  CORS-open, static import), gated by `redocly lint` in CI.
- **Slice 2 (ADR-0091)** — the **TypeScript** SDK `@webhook-co/sdk`: types generated by `openapi-typescript`
  (types-only, pure-node), a hand-authored hardened runtime, tsup dual ESM+CJS+`.d.ts`, npm OIDC provenance.
- **Slice 3 (ADR-0094)** — the **Python** SDK `webhook-co`: pydantic v2 models generated by
  `datamodel-code-generator` (open enums, scalar-RootModel collapse, forward-compatible), a hand-authored
  httpx runtime, `py.typed`, PyPI trusted-publisher release.
- **Slice 4** — the **Go** SDK `github.com/webhook-co/webhook-go` (a dedicated repo, per Go's module
  convention): hand-written structs (Go's OpenAPI tooling doesn't yet parse 3.1), a zero-dependency stdlib
  `net/http` runtime, tag-based release with `sum.golang.org` integrity + an auxiliary sigstore attestation.

Every SDK carries the identical hardened behaviour — bearer auth + secret redaction, idempotency-gated
retries with jitter honouring `Retry-After`, a single reactive 401 refresh, no-redirect enforcement,
https-only base-URL resolution, a typed error taxonomy, and cursor pagination — verified against the CLI's
`api-client.ts` parity oracle and taken through adversarial security + correctness review.

## decision

### 1. Independent versioning, coordinated when the contract moves

Each SDK versions on its own registry's terms and releases via its own tag-triggered workflow (see
`docs/releasing-sdks.md`). There is deliberately **no** enforced single lockstep version across languages —
that fights each ecosystem's conventions. A coordinated release (all three at one version) is a documented
runbook to use when a contract change should ship everywhere at once; the drift guards ensure each SDK's
types match the spec at release time.

### 2. Honest, per-registry provenance tiering

npm gets full sigstore/Rekor/SLSA provenance; PyPI gets tokenless OIDC trusted-publishing (attestations
best-effort); Go gets checksum-DB integrity plus an auxiliary attestation. These are not equivalent, and
the docs say so — Go is never described as "signed like npm".

### 3. First publish stays human-gated

All release workflows are built and dry-run-exercised but publish nothing until a maintainer opts in
(npm `NPM_TOKEN`, a PyPI Trusted Publisher, or the first Go `v*` tag). This keeps the very first,
irreversible publish to each registry a deliberate action.

### 4. `packages/sdks` becomes the SDK manifest

The placeholder is replaced by a typed `SDKS` registry (`packages/sdks/src/index.ts`) — the single source
of truth for each SDK's package name, registry, install command, repository, and integrity model. Docs and
tooling consume it instead of hard-coding install strings.

## consequences

- A spec change now ripples through three drift guards (the golden `openapi.json`, the TS generated types,
  the Python generated models) plus a manual reconcile step for the Go structs — each failing CI (or the
  Go review) if not regenerated, so no SDK can silently diverge from the contract.
- The only remaining S7 work is the documentation site (Slice 6, Mintlify on `docs.webhook.co`), which
  consumes the same spec and documents all three SDKs. It carries founder-gated one-time dashboard steps.
- Adding a fourth language later is a well-worn path: generate-or-hand-write the typed core, port the
  hardened runtime, wire a tag-triggered release with that ecosystem's honest integrity model, add it to
  the `SDKS` manifest.
