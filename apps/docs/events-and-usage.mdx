---
title: "What counts as an event"
description: "How usage is measured — the single unit we count, and everything we never count."
---

Usage is measured in one unit: the **event**. There is no per-step, per-feature, or per-seat metering, and no capability is locked behind a tier — the same features are available whether you pay or not. This page is the whole model of what counts.

## An event is one capture, or one delivery

Exactly two things count as an event:

- **A capture** — a request reaches one of your endpoints and is stored.
- **A delivery** — an event is forwarded to one destination. Each destination is its own event.

So a webhook captured and forwarded to one destination is **two** events; forwarded to three destinations, **four** (one capture, three deliveries). Deliveries count because delivering does real work on your behalf — not to push you toward a tier, since every feature is available on every plan.

## What is never counted

<Note>
  The most common surprises in usage-based products come from the things you _didn't_ think you were
  paying for. webhook.co counts none of them.
</Note>

- **Retries.** A delivery counts once, when it's first dispatched — however many attempts [the fixed exponential schedule](/concepts/delivery-retry-signing) takes to land it. A receiver's downtime is never your cost.
- **Duplicates that dedup collapses.** When [deduplication](/deduplication) recognises a retry as the same event, it never becomes a second captured event.
- **Verification handshakes.** A provider's `GET` or echo challenge is a control message — it is never stored and never counts.
- **Reading your own data.** Listing events, inspecting payloads, tailing, and replaying cost nothing on any surface. (A replay that _forwards to a destination_ is a delivery, and that delivery counts.)

<Warning>
  Turning [deduplication](/deduplication) **off** means every retry a sender sends is a distinct
  captured request, and each one counts. That's the trade you're making when you disable it — the
  default is off precisely so you see every request while you're getting set up.
</Warning>

## How usage relates to pricing

The pricing model follows from the unit above, and from two principles:

- **Single-dimension and disclosed up front.** You are metered on events and nothing else. The unit is stated where you create an endpoint, so there's never a hidden counter.
- **A soft cap that pauses, not a surprise bill.** The design is to alert you as you approach a limit and then **pause capture** rather than run up an overage — your captured data stays exactly where it is, and you resume by raising the limit.

## Check your usage

Your current usage is available on every surface:

<CodeGroup>

```sh CLI
wbhk usage
```

```sh API
curl https://api.webhook.co/v1/usage \
  -H "Authorization: Bearer $WEBHOOK_API_KEY"
```

</CodeGroup>

The dashboard shows the same figure at [app.webhook.co/usage](https://app.webhook.co/usage).
