The API authenticates with a bearer token — a `whk_`-prefixed API key you create in your [dashboard](https://app.webhook.co). Send it in the `Authorization` header on every request; there is no other auth scheme.

```sh
curl https://api.webhook.co/v1/whoami \
  -H "Authorization: Bearer $WEBHOOK_API_KEY"
```

The SDKs take the key at construction and attach it for you:

<CodeGroup>

```ts TypeScript
import { WebhookClient } from "@webhook-co/sdk";
const webhook = new WebhookClient({ apiKey: process.env.WEBHOOK_API_KEY! });
```

```python Python
from webhook_co import WebhookClient
client = WebhookClient(api_key=os.environ["WEBHOOK_API_KEY"])
```

```go Go
client, err := webhook.NewClient(os.Getenv("WEBHOOK_API_KEY"))
```

</CodeGroup>

<Warning>
  Keep the key server-side. The SDKs redact it from errors and debug output, but it's still a
  credential — never ship it to a browser or mobile app. If one leaks, [revoke it](/leaked-api-key);
  revocation is the only remedy.
</Warning>

## Scopes

Every key carries an explicit set of scopes, and a key is granted only the scopes its job needs. A request missing a required scope gets `403 FORBIDDEN` — mint a narrowly-scoped key rather than over-provisioning one and handing every consumer the keys to the kingdom.

| Scope             | Grants                                                                            |
| ----------------- | --------------------------------------------------------------------------------- |
| `endpoints:read`  | Read endpoints, provider secrets, destinations, and subscriptions.                |
| `endpoints:write` | Create and manage endpoints, provider secrets, destinations, and signing secrets. |
| `events:read`     | List and read captured events, payloads, and deliveries.                          |
| `events:replay`   | Replay events to localhost or a destination.                                      |
| `triggers:write`  | Create and revoke [agent triggers](/mcp/wake-an-agent).                           |
| `audit:read`      | Read and verify the tamper-evident audit log.                                     |
| `billing:read`    | Read [usage and metering](/events-and-usage).                                     |

Resolve a key's org and scopes at any time with `whoami` — the fastest way to confirm a deployed key is the one you think it is:

```ts
const me = await webhook.whoami();
console.log(me.orgId, me.scopes);
```

The CLI exposes the same call as `wbhk whoami`.

## Managing keys

Create, rotate, and revoke API keys from **Settings → Credentials** in the [dashboard](https://app.webhook.co). Keys are managed from the authenticated dashboard rather than minted over the API, precisely because they're credentials — the API surface never hands out a key that could act as your org. A key's secret is shown once at creation; store it in your secret manager, not in source.

## Signing in from the CLI

You don't have to paste a key into the CLI. `wbhk login` runs a browser-based OAuth flow (PKCE) and stores a short-lived, scoped key in your OS keychain; it refreshes silently, and `wbhk logout` revokes it server-side.

```sh
wbhk login              # browser OAuth (PKCE)
wbhk login --device     # device flow, for headless machines
wbhk login --api-key    # or paste a whk_ key directly
```

A device you've logged in from can mint keys of its own — if a laptop is lost or a CI runner is compromised, revoke the _device_ and every key minted under it goes with it. See [recovering a leaked key](/leaked-api-key#revoking-a-device).

## Base URL

The default is `https://api.webhook.co`. Point the SDKs at a self-host or dev origin with the base-URL option — it must be `https` (loopback `http` is allowed for local dev only), so a misconfiguration can't downgrade your bearer key onto a plaintext connection where a proxy could read it.
